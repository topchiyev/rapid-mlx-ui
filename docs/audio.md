# Audio backend

`core::audio` provides import validation, explicit microphone capture, local multipart transcription, serde transcript records, and composer insertion. It does not activate models, schedule inference, or write to the Store. The desktop integration must persist the selected ASR model and each job, acquire the shared chat/ASR inference guard, verify readiness and served identity, and persist results/edits using its normal Store transaction. Restore active jobs as interrupted; never resubmit them automatically.

## Supported models

STT is limited to the tested `mlx-community/Qwen3-ASR-0.6B-5bit` and `mlx-community/nemotron-3.5-asr-streaming-0.6b` repositories. Other STT models and variants, including Whisper and Voxtral, cannot be selected, loaded, connected, or used for transcription. Existing weights and transcript history are preserved; unsupported saved selections remain unavailable until explicitly changed. Repository matching is exact and case insensitive. Managed loading requires a matching Hugging Face cache identity and ASR family; arbitrary custom copies with unverified repository identity are inventory only. External services must advertise the exact selected supported repository identity, optionally with a revision. The existing HTTP transcription path remains; the abandoned Voxtral CLI adapter has been removed. Model-management UI redesign is deferred.

## Verified runtime contract

Read-only inspection of installed Homebrew rapid-mlx **1.0.2**, `rapid_mlx/routes/audio.py` (`create_transcription`, `_SUPPORTED_AUDIO_FORMATS`, `MAX_AUDIO_UPLOAD_SIZE`) and `api/models.py` (`AudioTranscriptionResponse`) confirms:

- `POST /v1/audio/transcriptions` accepts multipart `file`, `model`, `language`, `response_format`. The adapter always sends the selected model explicitly and requests `verbose_json`. Returned fields are `text` and optional `language`, `duration` (seconds), and `segments`.
- Both supported STT models use this same HTTP adapter. A real Qwen3-ASR response returns `language` as `["English"]`; other engines return a scalar string, null, or omit it. The shared parser accepts those shapes and joins arrays into comma-separated detected-language labels (empty arrays mean unavailable). Text remains required; invalid JSON or field types produce specific errors without echoing response values. The captured [Qwen speech response](../fixtures/runtime/asr-qwen3-response.json) complements the scalar-language fixture.
- Maximum file payload is 25 × 1024 × 1024 bytes. The app's defaults are 25 MiB and 1,800 seconds; the duration limit is an app policy, not a server claim. Configured limits can be stricter.
- `temperature` appears in a schema class but is absent from the installed route signature. The adapter deliberately exposes no temperature option. Word timestamps, context, and forced alignment are not enabled by this adapter.
- The runtime advertises FLAC, M4A, MP3, MP4, MPEG, MPGA, OGG, Opus, WAV, WebM, AAC, CAF, AIFF and extra suffix aliases. **This app adapter currently validates/imports PCM WAV (8/16/24/32-bit) and float32 WAV only**, since other formats cannot yet be validated for content and duration with its installed Rust dependencies. It does not claim the entire server format set is supported by the app. Frontend integration must use `SUPPORTED_AUDIO_EXTENSIONS` (`["wav"]`) for its file picker and show WAV-only wording; MP3/M4A inputs are not enabled.

No live model was loaded or downloaded for these checks. This source profile is not proof of ASR model compatibility. The supervisor must launch the exact pulled local path using the verified offline/download-disable controls and ensure auxiliary assets are local. The route can itself load models; merely supplying a repository alias is not enough to guarantee offline behavior. Do not invoke this client before supervisor/catalog checks. Missing dependency/asset HTTP error bodies are returned as UI errors, without automatic installation, model changes, retries, or logging prompts/transcripts.

`TranscriptionClient::new(endpoint)` remains the unauthenticated constructor. `TranscriptionClient::with_credential(endpoint, Option<String>)` optionally accepts a current-run bearer token for an externally managed local ASR service. Both accept literal loopback HTTP addresses, disable proxies and redirects, and fix the route path. Remote/cloud inference endpoints remain outside the local-inference contract. The token exists only in a private sensitive Authorization header value: the client has no serde implementation, its Debug output is redacted, and transcript/job serde records contain no credential field. Never put it in saved endpoint URLs or preferences. A 401/403 yields an authentication error without echoing the server body; other server diagnostics redact the credential. No authentication retry occurs. `transcribe(path, model, language, limits, cancel)` reads and validates at most the file cap on a blocking worker, then uploads those same bytes. It bounds response bodies to 2 MiB and uses a 30-minute HTTP deadline. File validation never writes the imported original. A cancelled pre-dispatch request reports no unknown server work; cancellation after dispatch drops upload/response waiting and reports `server_outcome_unknown: true`. No ASR server cancellation identity has been verified. The integration must not display server-stop confirmation, kill an external server, or automatically retry. This nonstreaming adapter has no partial text before the complete JSON response.

## Recording lifecycle and staging

`Recording::start(state_root, limits)` is **only** for an explicit Record action. Invoke it off the render thread because device setup and OS permission requests can block. It opens the default microphone with cpal 0.18, accepts f32/i16/u16 input and encodes PCM16 WAV using hound 3.5. The callback feeds a bounded eight-buffer queue to a separate encoder thread; queue overflow, device errors, encoder I/O errors, empty capture, and duration/size limits are surfaced rather than silently losing samples. Encoder I/O failures are copied to `error()` immediately and also returned by Stop/Cancel. The UI must poll `error()` during recording and stop/cancel on error. The Stop/Cancel controls must remain accessible while permission/startup is pending.

`stop()` first drops the input stream, drains already queued buffers by joining the encoder, finalizes WAV, validates nonempty output, and returns `StagedAudio`. Frames may finish encoding while Stop is in progress; no encoder or writable recording handle remains after Stop returns. A synthetic lifecycle test checks the final frame count and verifies returned bytes remain unchanged. This structural test is not a real-device acceptance check. `cancel()` and dropping `Recording` release the stream, join the encoder, and remove staging. Errors also release owned resources. No external recorder process is used. Encoder limits stop writing; the UI must promptly stop/cancel after polling a limit error to release the device. Stream destruction is the device-release boundary; thread joining has no independent timeout.

The supplied state root must be the existing absolute `AppPaths` root (`~/.rapid-mlx-ui` in normal operation). Files are unique, exclusively created under `audio/tmp`, with Unix mode 0600 and directories 0700; staging/retention directories reject symlinks. Dropping `StagedAudio` removes its own new file only, after checking that its original state-root/audio/tmp directories are still directories and not symlinks. Changed staging paths are left for explicit recovery rather than followed for deletion. Keep this value alive throughout transcription, then drop it at terminal outcomes. `retain(state_root)` explicitly moves it to `audio/retained` and rejects a different root. Tests preserve external files when a staging directory is replaced by a symlink. Imported originals must never be wrapped as staged files. Crash recovery cleanup of abandoned app-owned staging and deletion of retained files remain caller responsibilities; do not recursively delete imported paths.

The macOS bundle must contain `NSMicrophoneUsageDescription`; sandboxed packaging must grant audio input. Permission denial messages point to Privacy & Security → Microphone and offer file import. This backend does not add bundle declarations. **Real microphone permission, denied access, and device-loss behavior have not been exercised.** Automated tests simulate encoding/cleanup and local HTTP (including credentialed multipart 401 and secret redaction); they never request microphone permission. Non-silent synthesized English speech passed with local Qwen3-ASR through the production Rust client. Earlier unsupported-model experiments remain historical evidence in [validation](./validation.md).

## Durable records and composer

`Transcript` is a serde value carrying the requested model identity, requested/detected language, original/edited text, segments, audio duration, client elapsed milliseconds, status, and cancellation distinction. Persist model revision and source/job references with the caller's job record. `TranscriptionOutcome` distinguishes results from cancellation; persist a cancelled job through the caller's Store even when there is no transcript response. A received response is not proof of a server-supplied model identity (the wire response has none), so the caller must preserve its verified model selection snapshot.

`insert_transcript(draft, text, InsertMode::Append|Replace)` only returns draft text. Append preserves the existing draft and adds a newline. Present an explicit append/replace choice when text already exists. Insertion never sends a message. Transcription durations do not enter model token totals.

## Current desktop integration

Chat dictation uses **Record voice** below the composer, **Stop recording**, and **Cancel dictation**. **Voice settings** opens transcription model setup. Recording is enabled only when the selected ASR runtime is ready and no other inference is active; the worker rechecks readiness before opening the microphone. A fixed job/session identity follows capture and transcription, so navigation does not redirect the result. Successful dictation is appended to the latest draft in the original session and linked to its saved transcript in one session checkpoint. The current composer's unsaved edits are preserved; background insertion uses the worker's latest saved draft. Transcript IDs make duplicate insertion commands harmless. Empty results add no newline. Cancellation or failure preserves the draft, and late cancelled results remain in history without insertion. Sending still requires an explicit Send/Enter action.

Only dictations explicitly started in the current UI run are automatically inserted. Restart restores saved drafts/history without automatically recording, retranscribing, or inserting an old result. A failed transcript/session save is reported; visible composer text and in-memory transcript text remain recoverable, while background draft insertion commits only after storage succeeds. The headless workflow checks do not certify microphone permissions or certify other STT models.

The desktop persists independent ASR selection, requested language, jobs, edits, and transcript references under the fixed app state root. It validates the ready served identity before uploading and serializes recording/transcription with chat. External Connect discovers advertised models without assuming a chat route; select the exact served ASR identity explicitly. External service asset/download policy remains its operator’s responsibility. Imported sources are never removed. App recordings are dropped at terminal completion unless retention was selected; retained paths are persisted, while retention failures preserve transcript text and show a warning. The bundle supplies the macOS microphone usage declaration. These wired controls still require the real-device/live-ASR acceptance checks listed in [validation](./validation.md).
