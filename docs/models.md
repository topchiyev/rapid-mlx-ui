# Local model inventory and operations

Model discovery is read-only and offline. App/session data belongs under `~/.rapid-mlx-ui`; the shared Hugging Face cache stays at its configured location. Deleting a conversation never removes weights; removing weights never removes sessions or transcripts.

The cache-root order is: explicit app override, `HF_HUB_CACHE`, `HF_HOME/hub`, `XDG_CACHE_HOME/huggingface/hub`, then `~/.cache/huggingface/hub`. Additional directories are explicit local model folders. Inventory records each model repository/revision and canonical load path and deduplicates overlapping paths. Within HF snapshots it discovers independent nested checkpoint/quantization folders to eight levels, preserving the repository, revision and cache root on each entry. A shared 100,000-entry traversal budget bounds each snapshot search, and directory links are not followed. Sibling checkpoints with missing shards remain incomplete without invalidating complete variants; callers must include the subfolder/load path in model selection IDs. It ignores dataset/space repositories and does not follow directory symlinks recursively. Ordinary HF weight symlinks are read without modification.

Discovery bounds metadata to 4 MiB, model traversal to eight levels and 100,000 files. It inspects `config.json`, safetensors, shard indexes, tokenizer/processor metadata, model type and quantization. Recognized ASR families also accept top-level NPZ weights, as used by MLX Whisper Small/Tiny; safetensors take precedence when both formats are present. NPZ-only chat, TTS, and unknown-family checkpoints remain unsupported. Missing/broken/unreadable files and unsafe indexed paths produce incomplete entries; GGUF/.bin-only weights are unsupported by the 1.0.2 profile. Unknown architecture/auxiliary compatibility remains unknown and requires an explicit load. Static presence is not a successful runtime load. Activation revalidates the exact saved path rather than selecting another model when files disappear, and blocked-load errors include the catalog reason.

Logical weight bytes count referenced safetensors lengths per model, or top-level NPZ lengths for recognized ASR checkpoints without safetensors. Shared blobs may be counted for multiple revisions, so these sizes are not unique physical disk usage. Available catalog size is a runtime manifest download estimate and may be unavailable. Deletion reclaim estimates remain unavailable when the backend cannot safely establish them.

## Available and pulled catalogs

`rapid-mlx models --json` returns `text`, `audio`, `video`, `image` arrays. Text entries use `hf_path`; audio entries use `hf_id`, `kind`, and family. `kind=stt` denotes ASR; TTS and aligners must remain separate. `models --cached --json` returns `cached`, `count`, `total_bytes`; rows include repo, alias, subfolder, state (`ok`, `unmapped`, `incomplete`, `external`), byte size, and optional chat-ready evidence. These do not replace direct revision discovery. Served `/v1/models` is only current runtime identity, never the entire available or downloaded catalog. Search/task filters run on parsed data in Rust: JSON must not be combined with incompatible CLI search/modality switches.

The backend fetches catalog JSON only on an explicit call. UI/database integration must supply observation timestamps/origin, persisted catalog freshness, settings and missing selection handling. No catalog refresh downloads weights. `runtime::advertised_models(endpoint, credential)` lists served identities through an authenticated, numeric-loopback GET `/v1/models` independently of chat/ASR route negotiation. It uses a three-second timeout, 4 MiB response bound, no proxy/redirects and validates/deduplicates nonempty IDs. A served ID alone does not certify ASR capability; attachment still checks role readiness and routes.

## Explicit pull

`ModelOperations::pull` accepts an exact `org/repository` and selected cache root. This API deliberately rejects local paths and ambiguous aliases. It launches `rapid-mlx pull <repository>` with `HF_HUB_CACHE` set and telemetry/update checks disabled; only this explicit transfer uses online Hugging Face settings. It never supplies `--request` (which could submit a support report), `--no-preflight`, a conversion flag or a shell command. Full-repository pulls can be larger than a single quantization variant; a UI must state this scope. `pull_reference(reference, repository, cancel)` additionally accepts an explicitly selected catalog alias after verifying that its current available-catalog mapping uniquely matches that repository. The command retains the alias so the runtime preserves its variant and pin; the transfer lease still locks the whole repository. The original `pull(repository, cancel)` delegates with the repository as its reference. Arbitrary revision/subfolder flags are not exposed. Alias success additionally requires a matching `ok` cached-catalog alias/checkpoint and locally usable files at its subfolder and advertised revision. An alias that the cached catalog only represents under a different equivalent alias remains unvalidated; a complete sibling is never substituted.

CLI progress is retained as bounded output with indeterminate activity; structured byte progress is unavailable. Cancel signals only the owned pull child, waits, and kills/reaps if necessary. Partial files remain visible as incomplete. A successful exit triggers local discovery validation before reporting success; it does not certify ASR auxiliary assets or architecture execution. Failure, insufficient disk space and cancellation preserve existing cache contents and require an explicit retry. No automatic retry/download occurs when chat/ASR starts.

## Confirmed cache removal

The [compatibility evidence](./compatibility.md) and [removal fixture](../fixtures/runtime/removal.json) establish that `rapid-mlx rm <exact-repository> --yes` removes **all cached revisions of that model repository**. The backend preview lists the cache root, exact repository and every current snapshot revision; an unavailable reclaim estimate is honest. The caller must display and explicitly confirm that exact preview. Missing confirmation, changed root/revision scope or app-known active use blocks dispatch. Arbitrary local source folders and aliases cannot be passed to removal.

`rm_command` calls Hugging Face `scan_cache_dir()` and `delete_revisions(*all_repository_commits).execute()`. The installed cache library owns shared-blob deletion and global-store accounting. The Rust backend does not recursively delete repository files. Safety checks reject repository/snapshot symlink roots and cross-repository revision-hash collisions. Full scope is rechecked immediately after executable probing and immediately before dispatch. Normal cache revisions must be distinct commit identities; custom malformed caches require manual review.

All runtime, download and inference controllers must share a `ModelUseRegistry`. A loaded cache snapshot locks its entire repository, including sibling revisions and subfolders. Removal obtains an exclusive lease through command completion. Active chat, ASR, download or another app-owned operation blocks deletion. External-service controllers must hold appropriate use leases or block removal while connected; the desktop conservatively blocks removal. The app cannot infer every other process reading a shared cache, and it never stops an external service to permit removal.

Actual reclaimed-byte reporting uses bounded filesystem measurement before/after, when available. It is a cache-size difference, not a claim about filesystem block allocation, compression or concurrent external writes. Refresh inventory after a terminal operation; preserved session/transcript references keep their original missing model identity.

## Remaining integration checks

Temporary-cache and fake-process tests cover backend contracts. Real cache garbage-collection behavior is additionally checked using the installed Hugging Face library against synthetic repositories only. User weights are never test inputs. Offline startup and text generation were subsequently checked with existing Qwen3.5 4B weights, and owned descendant cleanup is covered by fake-process tests; see [implementation validation](./validation.md). Live ASR assets, abrupt parent-watchdog behavior, native UI confirmation/progress, and complete restart walkthroughs remain acceptance gates. No real download or deletion of user weights was performed.

## Desktop integration safeguards

The desktop preserves catalog aliases when pulling a particular variant, and Pulled entries identify exact revisions and nested checkpoint folders. Model removal is unavailable while a runtime transition is pending or an external inference service is connected: external cache use cannot be enumerated reliably. Explicit disconnect leaves the external process alive; its operator remains responsible for any subsequent use of files outside app ownership. Runtime changes wait for an in-progress removal to finish. Existing owned services and transfers also hold repository-use leases.

Available catalog freshness is saved with the last successful runtime CLI response. Failed refreshes retain that last-good catalog and label it cached; a successful empty response clears old entries. Local discovery has a separate current read-only scan timestamp. Refresh never changes a session’s selected model.
